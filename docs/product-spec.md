# RedisShake Web 功能交互规格（草案）

更新日期：2026-09-23  
状态：功能范围、页面组织、首次初始化与 Web 重启接管已确认；字段默认值及运行状态细节为工程方案。哨兵读取与整库命令策略仍待回答。

## 背景与目标

- 面向个人和小团队自行部署，通过浏览器完成 Redis 单向迁移与长期增量同步。
- RedisShake 为同步内核，优先官方版本，必要时维护少量补丁。
- 界面使用中文，RedisShake 原始日志保留原文。
- 参考 RedisSyncer 的任务管理流程；原生 HTML/CSS/JavaScript 实现界面与共用组件。
- Docker 及 Linux/macOS 直接运行，x86_64/ARM64 均覆盖。

## 功能范围

包含：单管理员登录、连接管理、任务草稿与配置、预检、单向全量加长期增量、状态和日志、停止、重新全量、复制与删除任务、二次确认后清空所选目标 DB。

不包含：多用户和权限管理、Redis TLS、双向及防循环、暂停续传、自动重试、定时启动、外部通知、内置数据核验、应用写入冲突管理、云服务专门适配、数据类型/命令组筛选、SSH 隧道、远程 Agent、页面性能调节。

## 入口与导航

主导航为“同步任务”“连接管理”“设置”。登录后进入同步任务。

- 同步任务：任务列表 → 创建/编辑向导或任务详情。
- 连接管理：连接列表 → 新建/编辑连接表单。
- 设置：单管理员密码、版本与数据目录等必要信息；不扩展为用户管理。
- 面包屑返回列表，未保存编辑离开时提示保存或放弃。

## 首次初始化与登录

- 首次进入 Web 的初始化表单预填账号 `admin`、密码和确认密码 `RedisShake@123456`，用户可在提交前修改。账号为 3～32 位，以字母开头，仅含字母、数字和下划线；密码不能为空，最多 128 个字符。
- 表单校验通过后创建唯一管理员，跳转登录页；重复或并发提交不创建第二个管理员。
- 账号或密码不符合要求、两次密码不一致时使用统一错误弹窗，关闭后保留当前表单输入；初始化已由其他窗口完成时转入登录。
- 后续用账号密码登录，成功进入任务列表；失败给出通用提示并保留账号，不回显密码。
- 设置页提供修改密码与版本信息，不提供新增用户或性能参数。忘记密码的页面提示通过本机维护命令取得一次性重置码。
- 登录失效或 Web 重启不停止同步；执行器持续管理任务，重新登录后恢复查看和控制。
- 会话及密码重置维护命令采用 [运行设计](runtime-design.md) 的默认方案。

## 连接管理

### 表单与动作

- 通用字段：名称、类型（单机/哨兵/Cluster）、备注、Redis 认证方式。
- 单机：主机和端口。
- Cluster：入口节点；实际节点发现与可达性检查由后端执行。
- 哨兵：Sentinel 地址、主节点名称、Sentinel 认证；Redis 认证单独填写。
- 第一版不显示 TLS/证书上传选项。
- “测试连接”只使用当前表单值执行连接检查，不保存，也不启动同步。
- “保存”验证字段并持久化，返回列表并展示结果；连接失败不等于字段无法保存，但启动前必须通过预检。
- 密码保存后不回显原文；编辑时保留原密码，只有明确替换或清除才改变。

### 列表与复用

- 列展示名称、类型、脱敏地址、最近测试结果/时间、引用任务数和操作。
- 支持按名称或地址搜索；测试结果过期时不把历史成功显示成当前必定可用。
- 每个任务选择源连接和目标连接，无需重复录入。
- 被任务引用的连接禁止直接删除，展示引用任务入口。
- 修改连接增加配置版本；已运行任务使用启动时的快照，新运行使用更新后的配置并重新预检。

## 创建与编辑任务

采用四步向导：

1. **基本信息与连接**：名称、可选备注、源连接、目标连接；可跳转新建连接后返回。
2. **数据范围与规则**：源 DB 选择、一对一目标 DB 映射、Key 前缀/正则包含与排除、增量命令包含/排除列表；不提供类型筛选。
3. **写入策略与预检**：默认要求目标 DB 为空，可明确选择覆盖同名 Key；执行预检并按项展示结果。
4. **确认**：汇总实际连接、DB 映射、过滤规则、写入策略和内核版本，点击“启动同步”。

- 任意步骤可“保存草稿”；草稿至少有名称，未完成配置不能启动。
- 编辑仅限没有活跃运行的任务；历史运行及其配置快照不可覆盖。
- 一对一映射中一个目标 DB 只能对应一个源 DB；Cluster 目标只允许一个源 DB 映射到目标 DB 0。
- 正则由后端按内核一致的语法校验；界面标出错误行。建议提供手工输入示例 Key 的规则测试，不扫描真实源数据。
- 多 Key 命令必须全部 Key 通过筛选，否则整条跳过并记录过滤原因；不将命令拆成部分写入。规则说明及示例预览需要提示这种行为。
- “增量命令过滤”单独成组，提示“仅影响启动后收到的增量命令，不影响全量导入；被排除的更新、删除或过期命令不会写入目标”。命令名称可搜索选择，按内核定义标准化大小写和子命令名称。
- DB/Key 规则在全量及增量都生效，按源 DB 筛选后再一对一映射；排除优先。Key 的允许前缀与允许正则合并取“或”，全部允许项为空则放行；DB、Key 与增量命令三个维度之间取“且”。规则预览必须与固定内核一致，不能擅自把前缀与正则改为“且”。[上游过滤器](https://github.com/tair-opensource/RedisShake/blob/v4/internal/filter/filter.go)
- 规则预览区分全量和增量示例，不能将全量恢复产生的 SET 当成应受增量 SET 规则过滤的条目。
- 运行中不允许修改正在使用的配置；可复制为新草稿。
- 不提供写入速率、CPU 并发、线程或缓冲区设置；统一使用经过验证的默认参数。
- 启动前服务端重新核对配置版本、任务状态、并发容量及预检条件；页面上的通过结果不能绕过后端检查。

## 预检查

最少检查：源/目标身份与连接、认证、版本、拓扑及节点可达性、源复制能力、目标写入前提、DB 映射、规则合法性、目标空策略、内核制品存在与版本匹配、本地目录与资源前提。

- 预检不得通过真实删除或覆盖用户数据来试探写权限，也不自动修改 Redis 配置。
- 启动同步必需条件未满足时阻止启动，显示具体原因和处理建议。
- 不能预先穷举所有未来增量命令；运行中发现不兼容仍报错停止。
- 不将预检称为数据一致性核验。

## 任务列表与详情

列表建议显示：任务名、源 → 目标、运行状态、同步阶段、开始时间、最近状态更新时间、错误摘要及操作。

- 支持名称搜索、状态筛选，默认按最近更新时间倒序。
- 空状态提供“创建同步任务”，并提示先准备连接。
- 详情页包含概览、配置摘要、运行记录和日志。
- 日志可选择某次运行、分页查看或跟随末尾；暂停滚动只影响展示，不暂停任务。
- 展示日志加载失败、已轮转和历史日志已清理等状态；不以空白页面冒充没有日志。
- 只显示有真实来源的阶段与信息；无法识别全量/增量阶段时显示“运行中，阶段待识别”，不生成模拟百分比。
- 状态获取失败显示更新时间与失联提示，不直接推断内核成功或失败。

## 运行状态与按钮

建议将任务配置与运行记录分开：任务可有零到多次运行，同一任务最多一条活跃运行。

| 对象/状态 | 用户可见含义 | 可执行动作 |
| --- | --- | --- |
| 草稿/无运行 | 已保存配置，尚未执行 | 编辑、预检、启动、复制、删除草稿 |
| STARTING | 启动中 | 查看、停止 |
| RUNNING | 进程运行，阶段另行展示 | 查看、停止、复制为新草稿 |
| STOPPING | 正在停止，尚未确认进程退出 | 查看；禁止重复启动/清理 |
| STOPPED | 用户主动停止已完成 | 查看、编辑、重新全量、复制、删除 |
| FAILED | 启动失败、意外退出或同步出错 | 查看原因、编辑、重新全量、复制、删除 |

运行阶段单独记录为 UNKNOWN、FULL_SYNC 或 INCREMENTAL，仅在有可靠证据时更新。

- 全量完成并进入增量不结束任务。
- 未经用户停止而进程退出，即使退出码为 0，也需按持续同步意外结束处理，不显示数据迁移成功。
- “停止”请求有幂等性，先显示停止中，确认进程退出后才显示已停止。
- 达到默认 5 个活跃任务上限时，建议拒绝新启动并说明容量，第一版不隐式排队。
- Web 重启不更改运行状态，恢复后从常驻执行器读取原运行及日志；不重新拉起内核。
- 执行器不可达时在现有状态旁显示“执行器暂不可用”和上次更新时间，禁用控制操作，不把失联直接显示成同步完成。
- 执行器自身故障后按 [运行设计](runtime-design.md) 核对旧进程；未确认旧进程已结束前不能重复启动同一任务。

## 重新全量、复制与删除

- 重新全量只能从停止/失败状态发起，明确提示会从头读取源端，不会断点继续。
- 展示之前的失败原因、当前连接配置及目标策略；用户可独立执行目标 DB 清理。
- 重新运行生成新运行编号，保留上一轮日志与结果；不会自动改成覆盖模式。
- 复制仅复制任务配置和连接引用，生成新草稿，不复制运行状态或自动启动。
- 删除只移除任务及按保留策略处理其本地运行资料，不删除源/目标 Redis 数据。
- 活跃任务禁止删除；先停止，停止完成后再删除。

## 清空目标 DB

1. 在未运行任务的目标区域点击“清空目标 DB”。
2. 后端解析真实目标身份、所选 DB、关联活跃任务与权限前提，返回本次清理摘要。
3. 确认框展示目标名称、地址/拓扑、完整 DB 列表，以及清理不受 Key 过滤限制；Cluster 明确展示整个目标集群 DB 0。
4. 用户二次确认；建议输入目标连接名，避免仅误点按钮。
5. 服务端再次核对目标身份与配置版本，取得本工具内部的目标操作锁后执行；前后不一致则要求重新确认。
6. 展示每个 DB/节点的结果。部分失败或状态不确定不显示整体成功，不自动重试。
7. 清理结束后仍留在当前页，不自动启动同步。后续启动重新预检。

- 禁止清理与本工具活跃任务冲突的目标范围，禁止通过连接别名绕过。
- 不自动停止、清理或控制其他应用的写入。
- 确认过的清理请求需幂等处理；重复提交或网络重试返回同一操作结果，不重新执行清理以免删除之后新写入的数据。
- 清理成功表示已确认所选清理命令的结果，不表示外部应用此后不会写入。
- 清理删除 DB 的全部 Key，不删除 Redis Functions。[Redis 命令说明](https://redis.io/docs/latest/commands/flushdb/)
- 清理由执行器单独实现，内核自动清库选项必须关闭；复制流中 FLUSHDB/FLUSHALL 的处理与这个用户主动操作分别定义，见 Q-043。

## 通用界面与反馈

- 请求过程中按钮显示具体动作并防止重复提交；关键幂等性由后端保证。
- 表单校验和接口错误使用统一错误弹窗；运行错误在任务详情保留错误摘要和日志入口。
- 登录过期跳回登录页，保留安全的返回位置；不把连接密码放进 URL 或浏览器本地持久化。
- 原生共用组件至少覆盖表单字段、选择器、按钮、表格、分页、弹窗、提示、状态标识、步骤导航和日志查看。
- 页面和日志内容按纯文本安全渲染；键盘可操作表单与弹窗，提交失败保留可安全复用的表单输入。
- 视觉由实现方按简洁中文桌面管理界面设计，适配窄窗口；不额外开发原生移动端。

## 验收条件

- 普通操作无需编辑 TOML 或手动执行 RedisShake。
- 保存连接后可创建多个引用它的任务；连接编辑不会静默改变历史运行。
- 草稿与启动分离，字段、预检、并发及状态检查均由后端执行。
- 正常单向全量/增量、停止、失败、重新全量与日志查看形成闭环。
- 清理操作明确目标与范围，具备二次确认、任务互斥和部分失败反馈。
- 页面刷新和重复点击不产生重复运行或重复清理。
- 只展示真实运行状态，不宣称数据一致或提供尚未实现的恢复能力。
- 首次初始化、登录与修改密码可用；Web 重启后可以继续观察并控制原运行。

## 待核对与假设

- 增量命令过滤、不做类型筛选、多 Key 部分匹配整条跳过及中文界面已经确认。
- 管理员首次 Web 初始化、页面组织与本机单命令启动已确认；密码重置按运行设计采用本地维护命令签发一次性码。
- 日志/历史默认保留、最低系统版本、精确内核版本和依赖版本需在工程规格中固定。
- 状态划分、容量满时不排队、手工 Key 示例测试和清理确认输入为工程默认方案，最终规格集中列示。
